Write animations like you edit a video.

Record an algorithm as deterministic states, place it on a named track, adjust its timing, add keyframes and markers, then render any frame exactly.

Start authoring Open complete C++ example

Deterministic

The same global frame always resolves the same state. Seeking and frame stepping are reliable.

Editor-shaped

Tracks, clips, local sequences, duration, trimming, holds, keyframes, fades, and markers.

Memory-aware

Repeated frames and long holds are mapped lazily. Large algorithm states are stored only once.

Mental model

One playhead, many independent tracks

Every track receives the same frame. No object owns a clock and no observer chain coordinates updates.

Architecture

UML class diagram

The storyboard owns the clock and named tracks. A sequence is a lightweight editing view into that storyboard; it does not copy state or create another clock. Plotting and rendering remain outside the authoring model, so the same deterministic frame state can be tested without opening a Raylib window.

ownership / composition creation or scoped access

Header-only deterministic core

viz/core and viz/story depend only on the C++17 standard library. They are safe to use in tests, recorders, exporters, and headless tools.

Raylib boundary

viz/plot, viz/visual, and viz/math/Functions.hpp use Raylib types. They translate resolved state into pixels, lines, spheres, and cameras.

Quick start

Record first. Edit timing second.

Authoring a recorded algorithmC++17
viz::Storyboard storyboard(359, 60.0f);

// A nested sequence uses local frame numbers.
const auto sorting = storyboard.sequence("Insertion sort", 30, 300);

// The algorithm recorder returns one state per meaningful step.
auto& states = sorting.track<SortFrame>("Algorithm state");
states.clip(recordInsertionSort(values))
    .trim(0, recordedStateCount)
    .framesPerStep(10)
    .holdLast()
    .commit();

// Visual properties use keyframes rather than sampled snapshots.
auto& opacity = sorting.opacity("Opacity");
opacity.fadeIn(0, 20).fadeOut(270, 29);

sorting.marker(0, "Sorting begins");
sorting.marker(299, "Sorting ends");

// Renderers only ask what exists at the global frame.
if (const SortFrame* state = states.at(storyboard.frame()))
    drawBars(*state, opacity.at(storyboard.frame()).value_or(1.0f));
Sampled clips

Timing operations stay declarative

startAt(frame)

Places the clip using frames local to its storyboard or sequence.

trim(first, end)

Keeps the half-open source range [first, end).

duration(frames)

Resamples discrete states across an exact editor duration.

framesPerStep(n)

Displays each algorithm state for n timeline frames.

holdLast()

Extends the final state to the containing sequence boundary.

commit()

Finalizes placement. A builder may only be committed once.

Timing does not expand the state vector. A clip with 40 large snapshots still stores 40 snapshots after framesPerStep(20) and holdLast().
Precise semantics

How a sampled state is chosen

Clip timing is evaluated when at(globalFrame) is called. Repetition, resampling, and holds never materialize extra copies of T.

source states→trim→framesPerStep→duration resample→scope clip / hold

Natural duration

After trimming, S states with framesPerStep(R) have a natural duration of S * R timeline frames.

Requested duration

duration(D) nearest-neighbor resamples that repeated virtual sequence to exactly D authored frames, preserving both endpoints.

Equivalent frame-mapping formulaNo expanded state vector
// S = selected states, R = framesPerStep, N = S * R
// D = duration if supplied, otherwise N
local = globalFrame - clipStart;

if (holdLast && local >= D)
    return states.back();

repeatedIndex = local;
if (durationWasSupplied && D > 1 && N > 1)
    repeatedIndex = llround(local * (N - 1) / (D - 1));

sourceIndex = min(repeatedIndex / R, S - 1);
return states[sourceIndex];

Rules that matter while editing

SituationExact behavior
Frame numberinglastFrame is inclusive. A storyboard from frame 0 through 359 contains 360 frames.
Local placementstartAt(0) means the containing track or sequence start. It is converted to a global frame only at commit().
Builder call orderduration() and framesPerStep() store settings, so their call order does not matter. trim() always addresses the original supplied source vector.
Sequence boundaryIf an authored clip runs past its scope, it is truncated at the boundary. The visible prefix is not compressed to fit.
holdLast()If the authored duration ends early, the last selected state continues through the track's scope end. It never crosses that boundary.
Overlapping clipsThe most recently committed clip wins for every overlapping frame. This is intentional layer-style override behavior.
Empty frameStoryTrack<T>::at() returns nullptr outside its scope or where no clip contributes a state.
FPSFPS controls how quickly playback advances. It does not change clip lengths, keyframe positions, or deterministic seeking.
Large requested durations do not create large allocations. The duration is arithmetic metadata. The actual memory cost is dominated by the selected source states and the number of committed clips.

Lifetime and performance rules

  • A Sequence is non-owning. Do not use it after its Storyboard is destroyed.
  • Track references returned by a storyboard refer to storyboard-owned objects. Keep the storyboard alive while using them.
  • A StoryTrack::at() pointer refers to a state owned by that track. Do not retain it across later clip commits; resolve once per rendered frame.
  • KeyframeTrack::at() returns an optional<T> value, not an internal pointer.
  • Resolving a sampled state scans committed clips newest-first: worst-case cost is linear in clip count, not in authored duration.
  • Resolving a keyframe uses binary search: logarithmic in keyframe count, plus the cost of copying/interpolating T.
  • framesPerStep, duration, and holdLast add constant metadata; they do not duplicate snapshots.
For very large algorithm states, store immutable shared data inside each snapshot (for example shared_ptr<const Graph>) and keep only the changing frontier, indices, colors, or annotations by value. Another good option is event recording plus periodic checkpoints. The timeline intentionally does not impose one storage strategy.

How to use the design

Practical authoring recipes

1. Record a complex algorithm without coupling it to drawing

Define a small render snapshot, run the algorithm once, and append a snapshot only at meaningful transitions.

Recorder patternDeterministic input to the timeline
struct SearchFrame {
    std::vector<int> frontier;
    std::vector<bool> visited;
    int activeNode = -1;
};

std::vector<SearchFrame> recordBfs(const Graph& graph, int start) {
    std::vector<SearchFrame> result;
    // Run BFS normally. After enqueue/dequeue/visit:
    // result.push_back({frontierCopy, visitedCopy, activeNode});
    return result;
}

auto& bfs = storyboard.sequence("BFS", 30, 300)
                      .track<SearchFrame>("State");
bfs.clip(recordBfs(graph, 0))
   .framesPerStep(8)
   .holdLast()
   .commit();

The algorithm never calls Raylib, reads the playhead, or waits. This makes recording testable and seeking exact.

2. Edit one recording into several pacing variants
Same state type, different editorial timingClips store only selected snapshots
auto recorded = recordAlgorithm(input);
const std::size_t recordedStateCount = recorded.size();

track.clip(recorded)
     .trim(0, 20)
     .framesPerStep(12)
     .commit();

track.clip(std::move(recorded))
     .trim(20, recordedStateCount)
     .startAt(240)
     .duration(90)
     .holdLast()
     .commit();

Because clip() takes its vector by value, the first call copies recorded; the second explicitly moves it. For large snapshots, plan ownership intentionally.

3. Synchronize state, camera, opacity, and annotations
Every layer reads the same frameNo observer graph
const int frame = storyboard.frame();

const AlgorithmFrame* algorithm = stateTrack.at(frame);
const float opacity = opacityTrack.at(frame).value_or(1.0f);
const Vector3 camera = cameraTrack.at(frame).value_or(defaultCamera);
const auto markers = storyboard.markersAt(frame);

if (algorithm)
    drawAlgorithm(*algorithm, opacity);
for (const auto& marker : markers)
    drawAnnotation(marker.name);
4. Add editor-style transport controls
Raylib inputCall once per loop
if (IsKeyPressed(KEY_SPACE)) storyboard.togglePlay();
if (IsKeyPressed(KEY_RIGHT)) storyboard.next();
if (IsKeyPressed(KEY_LEFT))  storyboard.previous();
if (IsKeyPressed(KEY_R))     { storyboard.pause(); storyboard.reset(); }

// Numeric seek can come from a slider, marker, or command.
if (const auto frame = storyboard.findMarker("BFS/Finished"))
    storyboard.goTo(*frame);

storyboard.update(GetFrameTime());

reset() preserves play state, so pair it with pause() when the desired UI action is “stop and rewind.”

5. Design state for large graphs, matrices, or simulations
Share immutable bulk dataCopy only changing metadata
struct GraphFrame {
    std::shared_ptr<const GraphGeometry> geometry; // shared by every frame
    std::vector<NodeStyle> styles;                 // changes per step
    int activeNode = -1;
    std::string caption;
};
  • Prefer one snapshot per meaningful algorithm step, then control pace with framesPerStep.
  • For sparse changes, store events and reconstruct snapshots at checkpoints before authoring the clip.
  • Keep GPU textures, fonts, models, and other Raylib resources outside snapshots; store stable IDs or references with clearly managed lifetime.
  • Use storedStateCount() in diagnostics to confirm timing edits did not inflate storage.
6. Add your own renderer or domain state

StoryTrack<T> has no domain constraints beyond storing T in a vector. Write a renderer that accepts const T& and call it only when at() succeeds.

Troubleshooting

Common problems and fixes

SymptomCause and fix
CMake says raylib.h was not foundSet -DRAYLIB_SRC to the directory that directly contains raylib.h, not the repository root. Or build only the headless core with -DTIMELINE_BUILD_EXAMPLES=OFF.
CMake says libraylib.a was not foundThe configured Raylib source directory has not produced the expected static library. Build Raylib first or point at a directory containing both the header and libraylib.a.
You only have raylib.lib on MSVCThe current CMake file explicitly imports libraylib.a. Use the compatible static archive used by this project, build core-only, or adapt IMPORTED_LOCATION and platform linkage for the MSVC library format.
Linux link errors mention GL or X11Install the OpenGL/X11 development packages for your distribution. Static Raylib also needs its system dependencies; this project links GL, X11, threads, m, dl, and rt.
Executable is not directly under buildVisual Studio and other multi-config generators place it under build/Debug or build/Release. Match the --config used for building.
track.at(frame) is nullptrThe frame is outside the track scope or no committed clip covers it. Check global versus local frames, call commit(), and use holdLast() when the state should persist.
keyframes<MyType>() throwsOnly floating-point types have a default interpolator. Pass a callback returning MyType from two values and alpha.
Reusing a track name throws logic_errorThe name was already registered with a different type, sampled/keyframed kind, or scope. Choose a distinct name or request it through the identical storyboard/sequence scope.
A clip ends at the sequence boundaryScopes are hard boundaries. Longer clips are truncated without time compression. Shorten duration, begin earlier, or enlarge the sequence.

Verification and extension

Test behavior without rendering

Extension guide

New domain visualization

Create a snapshot struct, a pure recorder returning vector<T>, and a renderer accepting const T&. The timeline core needs no modification.

New interpolated type

Supply a KeyframeTrack<T>::Interpolator. Add tests for endpoints, midpoint, easing, first/last holds, and out-of-scope lookup.

New easing enum value

Extend Easing and applyEasing, then test alpha below zero, at 0, midpoint, at 1, and above 1. Existing interpolators need no changes.

New plot or renderer

Keep Raylib includes under viz/plot or viz/visual. Consume resolved state; do not add clocks or mutable playback to visual objects.

Current boundaries

  • The authoring API is programmatic; there is no interactive GUI timeline or serialization format yet.
  • Playback is forward-only and stops at the end; looping, reverse playback, and speed scaling are application responsibilities.
  • Tracks, clips, markers, and keys can be added or replaced as documented, but there are no erase APIs.
  • Plot3D exposes a fixed camera by const reference; animate your own Camera3D keyframe track when you need editable camera motion.
  • Clip lookup is a newest-first linear scan. If one track grows to thousands of clips, add an interval index while preserving newest-clip precedence.
  • The classes provide no internal synchronization. Finish authoring before concurrent reads, or protect mutation and access in the application.
  • Audio, export, text layout, axes labels, legends, and general scene-graph ownership are outside the present scope.
A contribution is complete when its deterministic behavior has a headless test, invalid inputs have explicit outcomes, Raylib remains outside viz/core and viz/story, and this reference is updated with the public signature and semantics.
Timeline Storyboard keeps animation authoring editor-like while preserving a deterministic, testable C++ core.
